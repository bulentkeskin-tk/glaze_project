Glaze

A lightweight Slack coffee-chat bot — the open-source Donut alternative

Python 3.11+ FastAPI Slack Bolt Supabase OpenAI AWS Lambda

✅ Implemented Features

  • ✓
    Auto-enrolment — all members of a designated channel are enrolled on first cycle sync
  • ✓
    Opt-out / opt-in — /glaze-off and /glaze-on slash commands; also Home-tab buttons
  • ✓
    Frequency settings — weekly / bi-weekly (default) / monthly per user, via command or Home tab
  • ✓
    Snooze mode — pause for 1–4 weeks; stored as snooze_until date in Supabase
  • ✓
    No-repeat matching engine — greedy scoring favours never-met pairs, then least-recently-met
  • ✓
    Cross-department prioritisation — configurable bonus score for cross-functional pairs (default +20)
  • ✓
    Group DM creation — conversations.open called automatically for every pair
  • ✓
    AI icebreakers — GPT-4o-mini; falls back to curated local list when OpenAI is unavailable
  • ✓
    Thursday nudge — checks for human messages in the DM; silently skips pairs that already talked
  • ✓
    No message storage — conversation history is read, checked, and discarded immediately
  • ✓
    Admin dashboard + trigger endpoints — password-protected HTML UI and token-protected task routes

Matching Engine — matching.py

Scoring formula

score_pair(a, b, today):
  never_met_bonus = 1 if no history else 0
  last_met_days   = 10_000 if no history
                    else (today − last_meeting).days
  cross_dept_bonus = 20 if different departments
  return (
    never_met_bonus × REPEAT_PENALTY_DAYS
    + cross_dept_bonus
    + last_met_days
  )

Higher score = better pair. Never-met bonus (default 3 650 pts) dominates all other factors. Cross-department adds 20 pts on top.

make_pairs() — greedy loop

while len(remaining) >= 2:
  best = max(combinations, key=score)
  pairs.append(best)
  remaining.remove(best.a, best.b)

leftovers = remaining  # odd-one-out

Key properties

O(n²) combinations per iteration — fast enough for org sizes under ~500. Odd-number leftovers are tracked in the API response for fairness.

Scheduler — run_cycle()

Steps

  1. Sync channel members from Slack API (pagination)
  2. Auto-upsert profile: bot/deleted users skipped
  3. Extract department from Slack profile or custom fields
  4. Query eligible users (active, not snoozed, frequency due)
  5. Load full match history → MatchingService
  6. Greedy pairing → pairs + leftovers
  7. For each pair: conversations.open → Group DM
  8. Post intro message + icebreaker
  9. Record glaze_pair_events row with intro_ts

Response payload

{
  "cycle_date":      "2026-03-17",
  "eligible_users":  12,
  "pairs_created":   6,
  "leftovers":       [],
  "pairs": [
    {"channel": "C0…",
     "a": "U1…", "b": "U2…"}
  ]
}

Triggered Monday 08:00 UTC by pg_cron or EventBridge. Also available via /glaze-run-now in-channel for testing.

Scheduler — run_nudges()

Thursday nudge logic

target_cycle = today − timedelta(days=3)
# pairs from Monday's cycle

for row in pairs_without_nudge:
  history = slack.conversations_history(
    channel=row['dm_channel_id'],
    oldest=row['intro_ts']
  )
  human_msgs = [m for m in history
    if m['user'] in {user_a, user_b}]

  if human_msgs: continue # already talking

  slack.chat_postMessage(nudge_text)
  repo.mark_nudge_sent(row['id'])

Privacy guarantee

No storage of message content

The history list is used only to check whether a human message exists. The content is never saved to the database — it goes out of scope immediately.

Idempotent

nudge_sent_at is set after first nudge. Re-running won't double-nudge a pair — the SQL query filters on IS NULL.

Deployment Options

Local dev

uvicorn app:app
--reload --port 3000

Expose via ngrok or Cloudflare Tunnel. Change Slack URLs for each tunnel session.

AWS Lambda

Mangum wraps the FastAPI app as a Lambda handler. Use API Gateway or Lambda Function URLs. Pair with EventBridge for scheduling.

# handler.py
from app import handler

Vercel / any ASGI

Deploy as a Python ASGI app. Use Vercel Cron or Supabase pg_cron to call the task endpoints.

pg_cron (zero-infra scheduling)

Run the cron.schedule() blocks in supabase/schema.sql once. Supabase fires net.http_post() to /tasks/run-cycle every Monday and /tasks/run-nudges every Thursday — no extra scheduler service needed.

Testing — test_matching.py

test_prefers_never_met_pairs

# 4 users: U1-U4, history shows U1↔U2 & U3↔U4 met
svc = MatchingService(history)
pairs, leftovers = svc.make_pairs(users, today)

pair_ids = {sorted(a, b) for a, b in pairs}

assert ('U1', 'U2') not in pair_ids
assert ('U3', 'U4') not in pair_ids
assert leftovers == []

Validates that the no-repeat logic forces the engine to choose cross pairs (U1↔U3, U1↔U4, etc.) over previously-met pairs.

What is tested

  • ✓Never-met bonus overrides all other scores
  • ✓All users are paired (no leftovers with even count)
  • ✓History map built correctly from pair_events rows

Pure unit test

No Slack client, no DB connection. MatchingService is fully stateless and takes plain data — easy to test in isolation.
